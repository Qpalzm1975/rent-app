The acceptance scenario: Sarah $250, Tom $260, Jack $240, Emily $250, all due Monday ($1,000 expected). Sarah, Jack and Emily pay with distinct references ($740 received); Tom's $260 becomes Overdue only after the grace period with a current feed (Awaiting Bank Update when the feed is stale). The $428 electricity bill splits $107 four ways; Sarah, Jack and Emily reimburse ($321); Tom's $107 stays outstanding; one $428 supplier debit links to the bill once. Net cash flow $740 + $321 − $428 = $633. Sarah and Emily are told apart by alias despite paying the same amount, and replaying the bank rows changes nothing.

## Provider and platform facts (rechecked 19 October 2026)

- Redbark API v2 is still beta; `2026-10-01.wattle` is still the only release. Pricing: Developer plan A$16/month with API and webhooks (7-day free trial). Redbark is a CDR Representative of Fiskil; consent lasts up to 12 months. Your own account, used for your own app, is within Redbark's stated use. Redbark lists about 85 Australian institutions, including the big four. **Your bank and account type are not yet confirmed.**
- Redbark sends no event for new transactions on an API-only feed, and disables a transaction webhook after one failed delivery, so the scheduled job is the primary path. Details: [REDBARK.md](REDBARK.md).
- Vercel: Hobby allows 300-second functions (Fluid compute) but runs cron jobs only daily, so Supabase Cron (pg_cron + pg_net + Vault) is the scheduler. Vercel does not support pnpm 11 natively; `vercel.json` pins it.

## Remaining steps for the owner

In order; [DEPLOYMENT.md](DEPLOYMENT.md) has the detail. Never put a banking password, API key or secret into chat or source code.

1. **Supabase:** create a project in Sydney; run both files in `supabase/migrations/` in order. Copy the project URL and a secret key (`sb_secret_…`) for `SUPABASE_SERVICE_ROLE_KEY`. The free plan is fine for setup and testing, but it has no automated backups; for real financial records use a plan with backups or keep your own scheduled dump (see OPERATIONS.md).
2. **Secrets:** run `node scripts/password-hash.mjs` for `OWNER_PASSWORD_HASH`; generate `SESSION_SECRET` and `CRON_SECRET` with `openssl rand -hex 32`.
3. **Redbark:** sign up (Developer plan or trial), create the runtime API key with `data:read` and `connections:write`.
4. **Vercel:** import the GitHub repository, add the environment variables from `.env.example`, deploy, and set `APP_ORIGIN` to the final URL.
5. **In the app:** sign in, add the property, rooms and tenants (for existing tenants, start from a week inside your bank history), connect your bank through Redbark's hosted consent, select the rental account, press Sync now once.
6. **Webhooks** (optional but faster): run `scripts/configure-redbark.mjs` with a temporary setup key, add the two secrets to Vercel, redeploy, then revoke the setup key.
7. **Scheduler:** add the two Vault secrets in Supabase and run `supabase/schedule.sql`.
8. **Activation checks and backups:** the checklist at the end of DEPLOYMENT.md, then a test restore into a separate Supabase project.

## Known limitations

- No opening-balance entry: existing arrears or credit at setup cannot be recorded; weeks before the bank history can be waived with a reason.
- A bill's amount, dates or supplier cannot be edited or voided after creation (only re-split or waived per share).
- A tenant cannot be given a second tenancy (room move) from the UI, and a tenancy's payment day and grace period cannot be edited after creation.
- Any change the provider makes to a posted transaction, including text-only changes, reverses its allocations and sends it to review. This is deliberately conservative.
- Notifications are in-app only; no email or push delivery.
- The full-ledger snapshot design suits one owner's volumes, not large portfolios.
- The Sites/Vinext preview path (`pnpm build`, `scripts/*` installers) is retained from the earlier environment and is not used in production.
- `pnpm-workspace.yaml` exempts the October 2026 security-release versions from the seven-day release-age rule; remove the exemption from 21 October 2026.
- The repository was made public on 19 October 2026 so it could be read. No secrets are committed, but you may want to make it private again.

## How to resume

1. `npm install -g pnpm@11.25.0`, then `pnpm install --frozen-lockfile` (Node 22.13+).
2. `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build:vercel`; CI runs the same on every push.
3. Change dependencies on a `claude/*` branch: the "Refresh lockfile" workflow regenerates `pnpm-lock.yaml` with pnpm 11.25.0, commits it to that branch and runs CI.
4. Where things live: financial rules in `lib/engine/` (`ledger.ts`, `matching.ts`, `commands.ts`), Redbark client and ingestion in `lib/bank/`, sync and persistence in `lib/server/`, schema in `supabase/migrations/` (append-only; never edit an applied migration), tests in `tests/`.
